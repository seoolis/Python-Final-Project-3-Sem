# Финальный проект на языке Python с использованием фреймворка "Django".

Необходимо разработать Web–приложение на фреймворке Django, целью которого будет рассказать пользователю сайта об определённой профессии в IT-сфере, которое будет выводить аналитику по определенной профессии.

Информация о профессии на сайте должна быть полноценной. Она должна включать себя как общую информацию об этой профессии, так и статистические данные, представленные с помощью инфографиков и диаграмм.

> Профессия для веб-приложения в текущем проекте — **backend-разработчик**.

**Требования к внешнему виду**

1. **Шаблон** всех страниц на сайте должен иметь:

— шапку (header), в которой будет логотип – название проекта, придуманное Вами;
— подвал (footer), содержащий полностью ФИО и академическую группу студента.
— левое меню, содержащее ссылки на все страницы сайта с соответствующими названиями.

2. **Главная страница**. Должна содержать заголовок, описание профессии (текст не менее 2000 знаков), а также тематически подобранные изображения для профессии (минимальное количество 1 шт).

3. Страница «**Общая статистика**». Должна содержать следующие табличные данные и графики (вся информация должна быть представлена одновременно в форме таблиц и графиков). Все таблицы и графики должны иметь соответствующие заголовки.

— Динамика уровня зарплат по годам (нужно учитывать все вакансии, даже те, у которых указана другая валюта, при этом среднее значение вилки зарплат необходимо перевести в рубли по курсу центробанка за первое число месяца, в котором была опубликована вакансия. Не стоит учитывать вакансии с зарплатой больше 10 миллионов рублей, будем считать их информацию некорректно заполненной.)
— Динамика количества вакансий по годам (нужно учитывать все вакансии, даже с любыми пустыми полями)
— Уровень зарплат по городам (в порядке убывания), при наличии валюты в вакансии делать аналогичную конвертацию, как и для динамики уровня зарплат по годам.
— Доля вакансий по городам (в порядке убывания) при подсчете учитывать все вакансии, даже с любыми пустыми полями.
— ТОП-20 навыков по годам. Наиболее высокочастотные навыки (по анализу поля: key_skills).

4. Страница «**Востребованность**». Должна содержать следующие табличные данные и графики (вся информация должна быть представлена одновременно в форме таблиц и графиков). Все таблицы и графики должны иметь соответствующие заголовки.

— Динамика уровня зарплат по годам для выбранной профессии (требования аналогичные, как и для динамики уровня зарплат по годам)
— Динамика количества вакансий по годам для выбранной профессии (требования аналогичные, как и для динамики количества вакансий по годам)

5. Страница «**География**». Должна содержать следующие табличные данные и графики (вся информация должна быть представлена одновременно в форме таблиц и графиков). Все таблицы и графики должны иметь соответствующие заголовки.

— Уровень зарплат по городам для выбранной профессии (в порядке убывания) - требования аналогичные, как и для динамики уровня зарплат по годам.
— Доля вакансий по городам для выбранной профессии (в порядке убывания) -требования аналогичные, как и для динамики количества вакансий по годам.

6. Страница «**Навыки**». Должна содержать следующие табличные данные и графики. Все таблицы и графики должны иметь соответствующие заголовки.

— ТОП-20 навыков по годам для выбранной профессии. Наиболее высокочастотные навыки (по анализу поля: key_skills).

7. Страница «**Последние вакансии**». При посещении страницы, необходимо выгружать из [API HH](https://dev.hh.ru/) в реальном времени IT-вакансии соответствующие выбранной профессии за последние 24 часа (максимум 10 штук, отсортированных по дате публикации вакансии). Элементы списка должны содержать следующие поля:

— Название
— Описание вакансии (*повышенная сложность, требует доп. GET-запроса);
— Навыки (в строку, через запятую) (*повышенная сложность, требует доп. GET-запроса);
— Компания;
— Оклад;
— Название региона;
— Дату публикации вакансии.

**Требования к системе администрирования**
    
1. Сайт должен иметь **штатную систему администрирования Django** приложения.

2. **Авторизация и аутентификация** для системы администрирования штатная.

3. В системе администрирования должна быть представлена возможность осуществления **CRUD-операции** (создание, редактирование, изменение, удаление) для изменяемых элементов страниц сайта.

4. **Предобработку и анализ** всех необходимых статистических данных (графики и таблицы) осуществлять локально. Результаты загружать на сайт через систему администрирования.

5. **Графики** оформлять в виде изображений и загружать как файлы.

6. **Табличные данные**, как и весь другой текст для сайта оформлять в формате HTML и загружать через текстовые поля в системе администрирования.
